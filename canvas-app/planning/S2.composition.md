## Main task and arrangement

The sequence site -> equipment -> start is laid out left to right as three columns, so the inspector's eye and the decision order match and every earlier choice stays visible. The main action "Start inspection" sits at the bottom of the right-hand confirmation panel, directly under the details it confirms, and is visible without scrolling in every state.

```
+---------------------------------------------------------------------+
| S2.R1 header: [Cancel]  eyebrow/title                               |  fixed 72
+---------------------------------------------------------------------+
| S2.R2 1 Site        | S2.R3 2 Equipment          | S2.R4 3 Confirm  |
| (list, scrolls)     | (list, scrolls)            | details          |
|                     |                            | messages         |
|                     |                            | [Start inspection]| fixed footer
+---------------------------------------------------------------------+
```

Widths at 1366: Site 360 | Equipment remaining (about 526) | Confirm 384, 24 px gaps, all three columns full body height (648 px at 768 tall). Independent scrolling of the Site and Equipment lists is a deliberate decision: it keeps the Confirm panel and Start fixed in view even if a site has many assets. Seeded data (3 sites, up to a few assets each) will normally not scroll at all. Feasibility of independent list scroll is for discovery.

## Regions

### S2.R1 Header (fixed)
- Eyebrow "NEW INSPECTION"; title "Choose equipment to inspect"; no context line.
- Leave action (left): "Cancel" text button with back glyph -> S1, nothing created (A6). Disabled while Starting.

### S2.R2 Site column (card; list is scroll owner)
- Card heading "1  Site" (step number in a 24 px primary-outline circle + section heading).
- Rows (selectable cards, min 72 px): site name (16 semibold) over "site code · region" (14 muted). Selected: primary tint, 2 px primary outline, check glyph.
- Actions: select a site (A3). Changing the site clears the equipment selection (A3) and resets S2.R4.
- States: Loading "Loading sites..."; no sites (defensive) "No sites available"; load failure error banner at top of card.
- Entry state: nothing selected (A2, round trip 1).

### S2.R3 Equipment column (card; list is scroll owner)
- Card heading "2  Equipment", with "at <Site name>" in muted text once a site is chosen.
- Rows (selectable cards, min 72 px), two lines: equipment name (16 semibold) + criticality tag at right ("HIGH CRITICALITY" in muted outline style, not semantic colour); second line "asset tag · equipment type" (14 muted).
- Actions: select equipment (A4).
- States:
  - No site selected: muted placeholder "Choose a site first." List area otherwise empty.
  - Site with no equipment: "No equipment at <Site name>" + muted "Choose another site." (A3 empty).
  - Loading after site change: "Loading equipment...".

### S2.R4 Confirm panel (card; fixed, not scrolling)
- Card heading "3  Confirm and start".
- Body (top): selected equipment summary as label/value pairs (labels 14 muted, values 16): Site, Equipment, Asset tag, Type, Criticality with multiplier ("Medium · x1.25"), Hour meter. Before selection: muted "Your selection will appear here." (A4 confirmation).
- Messages (between summary and footer, inline banners):
  - Type has no checklist questions: warning banner, label "Warning", "There is no checklist for <type> yet. Choose different equipment." Start disabled. (Pallet racking, Air compressor; create-screens S2 rationale.)
  - Start failure: error banner, label "Error", "The inspection couldn't be created. Your selection is kept; try again." Site and equipment remain selected (round trip 2).
- Footer (fixed at panel bottom): "Start inspection" primary button, full panel width, 56 px. Above it, when disabled, a 14 px muted reason line: "Choose a site and equipment to start" / "No checklist for this equipment type".
- Starting: button reads "Starting..." with spinner; Start, Cancel and both lists disabled so one tap creates one Draft (A5). Success -> S3 on the first stage.
- Inspector name and Built with are set by the system (A-2, R2) and are not shown as inputs.

## Reading and focus order

Header heading -> Cancel -> Site heading -> site rows -> Equipment heading -> equipment rows (or its message) -> Confirm summary -> message banner (if any) -> reason line -> Start inspection. Initial focus: the screen heading. After a site is selected, focus stays on that site row (the equipment list updates beside it, announced politely: "4 equipment at North Warehouse"). After equipment is selected, focus stays on that row; the summary update is announced politely. On Start failure, the error is announced assertively and focus remains on Start.

## Accessibility intent

- Step numbers plus headings make the sequence explicit without relying on position.
- Selection is shown by outline + check + "selected" state, not tint alone.
- Disabled Start always has a visible text reason.

## Viewport changes

- 1024 x 768: columns become Site 280 | Equipment remaining (about 352) | Confirm 296. Equipment row's criticality tag moves to the second line ("asset tag · type · criticality") so names are not truncated. Summary label/value pairs stack (label above value).
- 1366 x 650: lists get shorter (still more than 5 rows each); Confirm panel summary fits (6 pairs at 36 px + footer 96).
- 1920 x 1080: body capped at 1600 px, centred; the Equipment column absorbs extra width.
