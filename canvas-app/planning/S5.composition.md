## Main task and arrangement

Two jobs, side by side: checking answers (left, the larger scrolling column) and confirming the score that will be submitted (right, a fixed panel). "Submit inspection" sits at the bottom of the score panel, directly under the final score and band it submits, and is visible without scrolling in every state. There is no submit confirmation dialog: the panel itself is the confirmation, and nothing is submitted without the inspector pressing a clearly labelled button next to the outcome.

## Regions

### S5.R1 Header (fixed)
- Eyebrow "INS-nnnnn · REVIEW"; title "Review and submit"; context line as on S3.
- Left: "Back to checklist" text button -> S3 on the stage that was active, answers unchanged (A13, round trip 4). Disabled while Submitting.
- No right-side actions.

### S5.R2 Answers by stage (card; body is the scroll owner)
- Card heading "Answers" + muted summary "15 of 18 visible questions answered".
- Four stage sections in stage order, each with a section heading (18 semibold) and muted "N of M answered"; stages with no visible questions show the heading and muted "No questions in this stage".
- Rows (min 56 px, divider between rows), visible questions only (A-4), in sort order with 24 px indent per depth to preserve tree context:
  - Code (14 px purple, tabular) | question text (16, wraps, never truncated) | answer value at right, 220 px column (16 semibold; Number answers shown as entered).
  - Unanswered: muted "Not answered" with a hollow-circle glyph (not colour-only).
  - Critical-stop questions keep their "CRITICAL STOP" tag.
- Read-only: changing an answer means Back to checklist (S5 recomputes on every entry, round trip 4).
- No answers state (A15 precondition): the card body shows centred "No answers yet" + muted "Go back to the checklist to answer questions."

Three stacked parts; the middle one takes remaining space.
- **Headline (fixed top):** eyebrow "RISK SCORE"; 32 px score "62.5" + muted "/ 100"; large risk badge (48 px, full width) with band word, "CRITICAL · critical stop" when forced. Must equal S3's panel values (R8).

Each row: code (14 purple) + question text (14, up to 2 lines, full text exposed) + weight at right "+15" (16 semibold, tabular); critical-stop rows add the "CRITICAL STOP" tag. Empty: muted "No answers meet a risk condition."
- **Calculation and submit (fixed bottom):**
  - Calculation rows (14 px label left, 16 px tabular value right, 32 px each): "Subtotal" 50 · "x Criticality (Medium)" 1.25 · "Capped at 100" (only when applied) · "Critical stop override" Forces Critical (only when triggered) · divider · "Final score" 62.5 · High (16 semibold).
  - Unanswered notice (A-5, Q3; only when count > 0): warning banner, label "Warning", "3 visible questions are unanswered. You can still submit." Does not block Submit.
  - Error banner (Submit failure, A15/A-7): label "Error", "Submit didn't finish. The inspection is still a Draft and your answers are kept. Try again." Placed above the button, at the action's location.
  - "Submit inspection" primary button, full panel width, 56 px. Disabled with a muted reason line "Answer at least one question to submit" in the No answers state.
- Submitting: button reads "Submitting..." with spinner; Submit and Back disabled (no concurrent submit). Success -> S1 with its confirmation banner (A15), session cleared.

## Reading and focus order

Header heading -> context -> Back to checklist -> answers heading and summary -> stage sections and rows top to bottom -> score headline (score, band) -> contributing questions -> calculation rows -> warning/error banner -> Submit inspection. Initial focus: the screen heading. On Submit failure, focus stays on Submit and the error is announced assertively; the warning is announced politely on entry when present.

## Accessibility intent

- Score breakdown is presented as label/value text rows, readable in order as the derivation (subtotal, multiplier, cap, override, final).
- Band always shown as word plus score; unanswered state uses a word and glyph.

## Viewport changes

- 1024 x 768: answers column about 612 | panel 340. Answer value column narrows to 160 px and long values wrap. Contributing list shows about 4 rows before scrolling.
- 1366 x 650 (short): the headline compacts to one 64 px row (score left, compact band badge right) so the contributing list keeps at least 3 visible rows; calculation rows, notices and Submit keep full size. Accepted trade-off: fewer contributing rows visible at once, never a hidden Submit.
- 1920 x 1080: body capped at 1600 px; panel stays 400 px; answers column absorbs the width.
