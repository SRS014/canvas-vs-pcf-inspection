## Main task and arrangement

Main content: a large photo viewer on the right that takes all remaining space; it hosts viewing, adding and annotating in place, so the drawing surface is as big as possible and is never inside a scrolling region. The saved-photo list is a fixed-width column on the left and is the screen's only scroll owner. "Add picture" is the header's primary action (A-9: Add picture is the required capture path; no camera path is designed).

```
+---------------------------------------------------------------------+
| S4.R1 [Back to checklist]  INS-00042 · PHOTOS / Photos and annotation [Add picture] | fixed 72
+---------------------------------------------------------------------+
| S4.R2 Photos (3)   | S4.R3 viewer pane                              |
| [thumb] caption    |  toolbar: caption title ....... [Annotate]      | fixed 64
| [thumb] caption    |  +------------------------------------------+   |
| [thumb] caption    |  |   photo frame (photo + strokes overlay)  |   | remaining
| (scroll owner)     |  +------------------------------------------+   |
+---------------------------------------------------------------------+
```

Widths at 1366: list 360 | 24 gap | viewer pane 934. Body height 648 at 768 tall: viewer toolbar 64, photo frame area about 552 -> a 4:3 frame of about 736 x 552, centred. At 1366 x 650 the frame is about 580 x 435.

## Regions

### S4.R1 Header (fixed)
- Eyebrow "INS-nnnnn · PHOTOS"; title "Photos and annotation"; context line as on S3.
- Left: "Back to checklist" text button -> S3 with stage and answers restored (A13). Always enabled; leaving during Adding or Annotating discards the unsaved picture/strokes without confirmation (create-screens S4). Disabled only while a save is in progress.
- Right: "Add picture" primary button (opens the device's picture chooser). Disabled while Adding, Annotating or Saving, with the pane's mode label explaining why.

### S4.R2 Photo list (card; scroll owner)
- Heading "Photos" + muted count "(3)".
- Rows (min 88 px): thumbnail 96 x 72 (cropped to fill, 6 px radius) | caption (16 semibold, up to 2 lines, full text exposed) over an "ANNOTATED" purple tag when the photo has saved strokes.
- Selected row: primary tint, 2 px primary outline, check glyph, "selected" state.
- Only this inspection's photos (round trip 3). Newly saved photos appear and become selected.
- States: Loading "Loading photos..."; Empty "No photos yet" + muted "Use Add picture to attach one." (A10 empty); Load failure: error banner at top of the card with "Try again".
- While Adding or Annotating, the list is visible but not selectable (dimmed to 60% with the mode label in S4.R3 explaining), so a stray tap cannot discard work. Entry state: nothing selected (round trip 3 reset).

### S4.R3 Viewer pane (card; remaining space; never scrolls)
One region with four modes. The toolbar (64 px, fixed at the pane's top) and the photo frame (remaining height, fixed 4:3 aspect, photo fitted inside and letterboxed on a #0F2530 background) keep their positions across modes so the overlay always lines up with the photo.

- **Nothing selected:** centred muted message "Select a photo to view or annotate it." (or, when the list is empty, "Add a picture to get started.").
- **Photo selected** (R6, R7 viewing): toolbar left = caption (18 semibold) + "ANNOTATED" tag when strokes exist; toolbar right = "Annotate" secondary button (48 px). Frame shows the photo with its saved strokes overlaid in the same frame box. When strokes exist, a muted helper under the toolbar title: "Annotating again replaces the saved strokes."
- **Annotating** (A12; transparent drawing layer exactly covering the photo frame): toolbar left = purple eyebrow "ANNOTATING" + muted "Draw on the photo"; toolbar right = "Clear strokes" (text button), "Cancel" (secondary), "Save annotation" (primary). Frame gets a 2 px primary outline to mark it as the active drawing surface. Strokes draw in error red #B42318 at about 5 px (marking defects); the previously saved strokes are not shown while drawing (fresh drawing, per create-screens). Save -> strokes written to that photo's Canvas pen strokes column, returns to Photo selected with the new overlay; Cancel -> strokes discarded, returns to the same selected photo. Saving: "Saving..." busy, all toolbar buttons and Back disabled. Failure: error banner directly under the toolbar ("The annotation couldn't be saved. Your drawing is kept; try again.") with strokes left on screen.
- **Adding** (A11, after a picture is chosen): toolbar left = section heading "New photo"; toolbar right = "Cancel" (secondary) and "Save photo" (primary). Frame (reduced to leave room) shows the chosen picture; below it a caption field: persistent label "Caption", 48 px input, muted helper "Leave blank to use "INS-nnnnn photo 4"" (A-6 default). Saving: "Saving..." busy, no double save. Failure: error banner under the toolbar; picture and caption kept. Cancel discards the picture and returns to the previous selection state.
- Limits of the annotation (freehand only, strokes stored separately from the photo, no shapes/labels/markers) are not compensated by extra UI (R7).

## Reading and focus order

Header heading -> Back to checklist -> Add picture -> list heading -> photo rows -> viewer toolbar title -> toolbar actions left to right -> mode banner/helper -> frame -> caption field (Adding). After selecting a photo, focus stays on the row; the viewer change is announced politely. Entering Annotating moves focus to the "ANNOTATING" label; Save/Cancel return focus to "Annotate". After a photo is saved, focus moves to its new list row. Save results are announced; errors assertively.

## Accessibility intent

- The photo frame exposes the caption as its accessible name; "ANNOTATED" is a text tag, not an icon-only cue.
- Drawing is pointer-only by nature (R7 limit); every other action on the screen is reachable by touch targets of at least 48 px.
