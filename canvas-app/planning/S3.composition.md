## Main task and arrangement

Main content: the visible questions of the active stage, in a large left column that is the screen's only scroll owner. The live risk panel is a fixed right column the full height of the body, so score and band stay in view while scrolling and answering (R5, "legible risk state at a glance"). Stage tabs sit directly above the question list (they belong to it, not to the page). Forward actions "Photos" and "Review" are fixed in the header's right; "Abandon" is the header's leave action at the far left, physically separated from them.

## Regions

### S3.R1 Header (fixed)
- Eyebrow "DRAFT INSPECTION"; title = system inspection number "INS-nnnnn" (R2); context line "Equipment name · asset tag · Site · Type · Criticality xN".
- Left: "Abandon" text button (with a close glyph) -> confirmation S3.R5 (A16).
- Right: "Photos" secondary button (A10 -> S4), then "Review" primary button (A14 -> S5). Both 48 px. Always enabled, including the no-questions state (create-screens S3).

### S3.R2 Stage tabs (fixed, above the list, width of the question column)
- Four equal tabs in fixed order: Pre-use · Visual and structural · Operational test · Safety sign-off (A7). Each tab: stage name (16 semibold when active, regular muted when not) and a 14 px count "answered/visible" (e.g. "3/5") that updates live.
- Active tab: primary text, 3 px primary underline, white background; inactive tabs on the wash. Tabs are 56 px tall, full touch width.
- Switching keeps all answers (A7) and resets the list's scroll to the top of that stage. On return from S4/S5 the previously active tab is restored (A13, round trips 3-5).

### S3.R3 Question list card (remaining space; scroll owner)
- Content: the active stage's visible questions only, in sort order, each indented by depth (R3, R4). Depth 0-4 only; depth 5+ never appears (R4/R13, intentional) and no placeholder hints at it.
- Question row anatomy (min 72 px, 12 px vertical padding, 1 px #CBE2EC divider):
  - Indent: 32 px per depth level (max 128 px at depth 4) plus a 1 px #CBE2EC vertical connector in the indent gutter tying children to their parent. Depth-0 rows have 16 px extra top space to separate question families.
  - Text block (flexible width): question code (14 muted, tabular) on the first line with tags; question text (16 semibold) below, wrapping freely (never truncated). Tags after the code: "CRITICAL STOP" (purple tag) for critical-stop questions, so the inspector knows before answering.
  - Help toggle (only where help text exists): 48 x 48 "?" button labelled "Help for <code>"; expanded help appears under the question text as 14 px muted text with a 2 px secondary side rule; collapsed by default; per-question state kept while on S3.
  - Answer area (fixed 320 px at right, vertically centred on the text block), per answer type (R3):
    - Yes/No: two 48 px segmented options "Yes" | "No" (112 px each); selected = primary fill, white label, check glyph. A "Clear" text button (80 px) follows; its space is reserved so controls never shift, and it is shown only when answered (A9).
    - Choice: dropdown 48 px, full 320 px, options from the question's list, placeholder "Select an option"; first list entry "No answer" clears it (A9).
    - Number: numeric input 48 px, 160 px wide; clearing the field clears the answer. Invalid entry: 2 px error border and, under the input, error icon + "Not a valid number" (A8); it does not score.
    - Text: input 80 px tall (two lines), full 320 px; empty = unanswered.
  - The question text is the persistent label of its answer control.
- Behaviour on answering (A8/A9): newly visible children appear directly under the parent at their indent; children that no longer qualify (and descendants) disappear. The answered row stays where it is on screen and keeps focus; the list does not jump to the top. (Input focus and list reload stability is a DESIGN.md evidence item; if the platform resets focus or scroll on recalculation, discovery reports it rather than the design hiding it.)
- States:
  - Stage with no visible questions (A7 empty): centred "No questions in <Stage> for this equipment." + muted "Answers in other stages are kept."
  - No questions loaded (defensive): centred "This equipment type has no checklist questions." + muted "You can still add photos, review, or abandon." Tabs show 0/0.
  - Loading (first entry): spinner + "Loading checklist...", tabs disabled.
  - Load failure: error banner at top of the card, "The checklist couldn't be loaded." with "Try again" secondary button.

### S3.R4 Live risk panel (fixed right column, full body height; content-sized sections, own scroll only for a long critical-stop list)
- Purpose: current score, band and why (R5).
- Content, top to bottom:
  1. Eyebrow "LIVE RISK".
  2. Score figure 48 px "62.5" with muted "/ 100".
  3. Large risk badge (48 px, full panel width) with band word in 18 px semibold uppercase: "LOW", "MEDIUM", "HIGH", "CRITICAL"; Critical forced by a stop reads "CRITICAL · critical stop".
  4. Derivation lines (14 px, label left, value right, tabular): "Subtotal" 50 · "Criticality (Medium)" x1.25 · "Capped at 100" (only when applied) · "Critical stop" Forces Critical (only when triggered).
  5. "Critical stops" heading (16 semibold) and list: each triggered stop as error icon + code + question text (14 px, wraps). None: muted "None triggered". If the list exceeds the panel, only this list scrolls.
  6. Footer line (muted 14): "Answered 12 of 18 visible questions" (all stages).
- Before any answer: score "0.0", badge "LOW", derivation "Subtotal 0".
- Updates immediately after each answer (R5). Band changes are announced politely ("Risk now High, 62.5"); score-only changes are not announced, to avoid chatter.
- FL-32 is treated like any other question (Q5 default); the panel shows nothing about advanced rules.

### S3.R5 Abandon confirmation (modal dialog over the screen)
- Trigger: header "Abandon". Appears centred over a dimmed scrim (text colour at 40%), 480 px wide card; the underlying screen stays in place and keeps the active stage and scroll.
- Content: title "Abandon INS-nnnnn?"; body "Your answers will be lost. The Draft inspection stays on the home list without a score." (A16, Q2).
- Actions (right-aligned, 48 px): "Keep inspecting" (secondary, default focus) and "Abandon inspection" (destructive confirm, error fill).
- Focus: moves to "Keep inspecting" on open; focus stays inside the dialog; tapping the scrim does nothing. "Keep inspecting" closes it and returns focus to the header's Abandon button, with stage and answers intact. Confirm -> S1.
- If discovery finds a modal overlay cannot be supported, it returns the constraint for a design revision; builders do not substitute another pattern.

## Reading and focus order

Header heading (inspection number) -> context line -> Abandon -> Photos -> Review -> stage tabs left to right -> question rows top to bottom (within a row: code/tags -> question text -> Help -> answer control -> Clear / validation message) -> risk panel (score, band, derivation, critical stops, answered count). Initial focus on fresh entry: the screen heading; on return from S4/S5: the active stage tab.

## Accessibility intent

- Depth is conveyed by indent plus code nesting (FL-01.1.1); each row also exposes "level N" to assistive tech.
- Risk band always shows word and score; critical stops are named, not only coloured.
- All answer targets at least 48 px, with 8 px between Yes, No and Clear.
